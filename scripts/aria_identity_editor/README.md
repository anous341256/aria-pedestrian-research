# Aria 外观＋旋转：轨迹纠错工作台

## 新默认入口：轨迹片段审核（2026-09-27）

`http://127.0.0.1:8767/` 是片段优先界面；同一新库的旧式框对入口保留在 `http://127.0.0.1:8767/pairs`。启动器位置不变，已改为打开新入口。

由于旧服务重启受限，正式切换采用并行迁移：`outputs/aria_identity_editor/segments_v2` 保存新项目，完整继承 `v1` 的标签和事件历史；`migration.json` 记录迁移版本、数量与校验值。旧端口 8768、旧库 `v1` 和历史导出保持原样。**请停止在 8768 提交新审核**：迁移是快照，不是双向同步。需要逐框处理时使用新端口的 `/pairs`，不要回旧服务器。

1. 每批最多显示 20 个可疑片段，默认约 5 秒。黄色框是当前待审目标，灰色是其他检测；没有框的帧不插值。
2. 播放后点“这段身份正确”，只确认页面显示范围内的实际节点关系。成功后留在原处回看，再手动“下一段”。
3. 跟错时暂停，点“这里跟错了”。在前后约 1 秒中逐帧检查，点选最后一个正确框作锚点。帧号可输入后按“跳转”。
4. 点“生成后续候选”。最多三条分支与原推荐分开，使用同一视频时钟同步预览，不会同时解码四路视频。先选择预览，再“确认所选候选”。未选分支不会自动记为非同人。
5. 都不对时手动选择后续检测框，明确确认同人或非同人；没有可选框则“暂跳过”，不画框、不硬接、不补框。
6. 暂跳过进入稍后列表，不立即重新弹出。可重新打开检查。一次撤销恢复上一次完整片段操作；旧框对操作也兼容同一撤销历史。

片段由固定检测节点、时间范围及内容指纹识别，不以可变的轨迹数字 ID 识别。保存只做一次全局约束重算与一次版本导出。预览、暂停、选择锚点没有隐式监督。批量判断与旧人工标签冲突时整批拒绝，不覆盖旧判断。

筛选条件为代价 ≥ 0.45、竞争差值 ≤ 0.10、跨缺失帧、无效旋转，以及有续接候选的断轨端点。相近风险合并成 5 秒片段，连续窗口最多重叠 1 秒，风险连接只归属一个任务。大量单框/短片段仍会形成任务；不是只显示 20 个就代表总工作量已降到 20 次。

候选局部搜索最多向后 5 秒、跨 5 帧，束宽 12，展示最多 3 条不同序列。按累计关联代价和每个未匹配帧 0.55 的代价排序，束内保留不同早期走向。遵守已有人为同人/非同人与同帧唯一性；候选少则少展示。分数不是错误概率，也不是训练所得置信度。

新版首次读取旧库时，通过 SQLite 在线备份生成 `corrections_before_segments_*.sqlite3`，再增加批量事件字段。旧标签与历史导出不改写。新导出额外包含 `segment_reviews.json`，记录审核范围、节点、动作来源和观看时长；`human_direct` 仍仅代表身份关系，不能推断框位置是金标。

页面统计的是已提交且未撤销操作的观看时长、审核动作、确认关系和已解决风险关系，不是检测精度，也不代表所有独立错误均已消除。未提交的观看不计入该持久统计。

播放器提供“重新加载视频”和“逐帧兼容播放”。MP4 加载/解码失败时自动切换到已有 `/frame` 接口读取同一原视频的 JPEG 帧；这不是换视频或改检测坐标。兼容模式逐帧读取并同步画框，速度受解码/传输影响，不保证实时 10 fps。使用页面已允许的 data 图片来源，不放宽安全策略。切换模式、播放、暂停、逐帧定位不提交审核记录。媒体错误恢复测试：`node scripts/aria_identity_editor/test_media_recovery.cjs`。

真实数据副本验收报告位于 `outputs/aria_identity_editor/segment_smoke_v1/segment_acceptance.json`。测试没有往正式库写入人工判断。开发测试另运行 `node scripts/aria_identity_editor/test_segment_ui.cjs`，旧的列表性能测试仍保留。

## 操作方法

1. 系统优先列出有竞争候选、跨帧间隙、姿态无效等风险较高的连接。可播放连续视频或“这处前后片段”。风险是启发式排序，不是错误概率。
2. 看前后两张人框裁片，按 **1 同人、2 非同人、3 不确定**。裁片未加载完成时不能提交。
3. 同人：把这两个检测框置于同一身份，优先于自动关联。必要时拆开原来的自动连接，重新组合前后片段。
4. 非同人：禁止这两个检测框属于同一身份，不只是删除一条边；不能通过其他自动路径绕回来。
5. 不确定：保留反馈，但不施加身份约束。将此前的 yes/no 改为不确定，会撤销这条判断的硬约束；其他判断仍生效。
6. 右侧不是目标时，用“其他候选”切换；无需画框。也可停在任意帧，先选“设为前段”点击框，再跳到后帧选“设为后段”点击框。手动同人判断可以跨越自动关联的 5 帧窗口。
7. 每次确认后，当前视频中的 ID、轨迹图和导出版本直接更新。不会自动切走当前问题，便于观察变化；看完按“下一条”。小窗口可按“看纠错卡片”直接跳到判断区。
8. **Z / 撤销纠错**会恢复上一步约束，再重算轨迹。旧版本保留。导入的旧记录在“已保存的纠错”中可以选择修改；新工作台的撤销不删除旧审核库记录。

“下一条”按本轮打开页面时的顺序向后推进：纠错重算不会重排已排好的问题，新发现的问题追加到末尾，已经保存过判断的框对自动跳过。到末尾按钮显示“已到本轮末尾”，不会绕回首条。需要回看时可在下拉列表选择；刷新页面会开启新一轮排序，已保存判断不丢失。

下拉列表每页最多显示 100 条，通过“列表上一页 / 下一页”浏览。完整顺序保留在内存，同页点击“下一条”只切换选中项，不重建列表；跨页自动显示对应页。保存后只刷新当前页的审核状态。列表翻页本身不改变当前审核框对，选择其中一条才跳转。

如果两次“同人”会把同一帧不重叠的不同人放入一个 ID，或与“非同人”矛盾，系统拒绝该次操作并提示冲突；不会悄悄覆盖之前的确认。请先检查冲突判断，再修改或改为不确定。

## 当前实现（明确不是训练后的新模型）

冻结原 TrackTrack 实验的 YOLOX 检测缓存及 **2048 维 FastReID 外观特征**。将每个特征重新单位归一化，不运行新检测或重新提取外观。

输入框是 `tracker_input80` 的 5,513 个已有检测，不额外用置信度、长宽比或短轨迹长度丢框；因此包括原追踪器未输出的短片段和可能的误检。766 个轨迹片段**不等于 766 个真实行人**，也不能拿它与过滤后的 TrackTrack 轨迹条数直接判断谁更好。

几何使用此前背景实验的相对相机旋转。多帧变换按时间顺序相乘，`H = K R K^-1`，将前框四角投影后取水平外接框。无有效姿态或投影无效时，不伪造旋转：使用原位置的弱几何项并提高外观权重，该关联记录 `rotation_valid=false`。

固定、未训练的代价（越低越相容，不是概率）：

```text
A = min((1 - cosine_similarity) / 0.5, 1)
G = min(中心距离 / 源框对角线 / 2, 1)
S = min(mean(abs(log(候选宽高 / 投影框宽高))) / 1.4, 1)

有旋转：cost = 0.55 A + 0.35 G + 0.10 S + 0.02 (gap - 1)
无旋转：cost = 0.75 A + 0.15 G + 0.10 S + 0.02 (gap - 1)
```

没有 IoU 硬门控，没有卡尔曼或历史方向模型。先处理相邻帧，再处理 2–5 帧间隙；使用带未匹配选项的 Hungarian 一对一分配，仅接受 cost < 0.55。此阈值和权重是第一版工程默认值，未经此批人工反馈调优，不声称最优。

所有人工正约束先建立身份组件；自动关联不得违反同帧唯一性或任何负约束。组件按时间排成路径；正约束通过已有正约束传递出来的连接标记为 `human_transitive`。确认一对框不表示这条轨迹后续全部正确。

## 重复检测的处理

旧审核中第 416 帧，两个高度重叠的框都被确认与同一个前框同人。将其作为身份别名：仅在**人工同人链确认且同帧框两两 IoU ≥ 0.65**时，保留检测分数较高的框用于显示和导出，其余框存为别名。

本次保留 `f0416_d007`，显示中抑制 `f0416_d011`；原始检测与两条人工反馈均未删除。`duplicate_aliases.json` 可审计。没有对其他未经确认的重复框进行自动大范围合并。如果人工反馈有误，改判/撤销后别名和轨迹随之重算。

## 结果与导出

项目目录：`E:/New_research/outputs/aria_identity_editor/v1`。

- `input.json`、`features.npz`、`manifest.json`：固定输入、已导入反馈、参数与 SHA256。
- `automatic_baseline.json`：不施加人工反馈的初始轨迹，保留用于对照。
- `corrections.sqlite3`：实际纠错与追加式事件日志，独立于旧审核库。
- `exports/rev_000000`：应用旧反馈后的初版。每次修改/撤销生成新编号目录，旧导出不覆盖。
- 每个导出目录包含 `annotations.xml`（CVAT for video 1.1）、`labels.json`（person 标签与属性）、`tracks.mot.txt`、`provenance.csv`、`corrections.json`、`duplicate_aliases.json` 和校验 manifest。

CVAT 使用与当前去畸变片段相同的 600 帧、10 fps、2560×1920 视频，按 CVAT for video 1.1 导入 XML。标签为 person，附带 association_status、node_key、track_anchor、detector_score。没有上传或覆盖已有 CVAT 任务；若要在已有任务导入，应先确认标签属性兼容并保留备份。

CVAT 输出每个实际检测帧为关键帧，在所有缺口首帧和轨迹结束后显式写 outside，**不会在漏检区间插出框**。独立展开 XML 校验可见帧/ID/坐标集合。只在导出时把越界框裁到图像内，原始框坐标不变。

状态含义：`human_direct` / `human_transitive` 仅说明进入该框的身份关系；`automatic` 为自动关系；`seed_unreviewed` 为起点。没有任何状态表示框位置是人工修正真值，整条轨迹也不自动升级为金标。

本次初始可见框 5,512 个（另 1 个已确认重复框为别名）、轨迹片段 766 个、自动连接 4,727 条、人工直接/传递连接 19 条，所有 20 条同人和 14 条非同人约束均满足。数字是结构计数，不是精度指标。

## 验证与边界

单元测试覆盖外观关联、否定后禁止间接重新合并、同人覆盖自动边、矛盾不落库、同帧重复框、无姿态降级、缺口不插值、纠错落库、撤销、重启恢复和过期版本拒绝。

浏览器端在独立 `ui_smoke` 副本验证了真实视频框对的“否定→不同 ID”“肯定→同 ID”“撤销→恢复”及导出，测试判断不写入正式库。

目前不解决框的位置精修、漏检、长期遮挡、误检剔除或学习权重，也没有定量证明这版关联比原方法好。它完成的是**预关联—纠错—身份生效—版本导出**闭环，为后续训练积累可追溯监督。

Aria 在此仅作为标注/诊断辅助，离线姿态插值及用户后验纠错不能算作严格在线或 RGB-only 预测成绩。正式轨迹预测研究仍需独立测试录制，不能把被用来纠错/调参的片段当作未见测试数据。

服务只绑定 127.0.0.1；写请求检查来源、令牌和版本。不自动上传、训练或改动原始 VRS、检测缓存、TrackTrack 与 CVAT。
