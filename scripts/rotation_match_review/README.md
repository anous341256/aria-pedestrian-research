# 旋转补偿：三条件单步匹配与轻量人工纠错

## 使用

双击项目根目录 `Open_Rotation_Match_Review.cmd`，或在服务已启动时打开 <http://127.0.0.1:8766>。

1. 左边是上一帧待找的人，右边是当前帧的一个候选。两边都有放大裁片和完整画面；完整画面可点击放大。
2. 按 **1：同一个人、2：不是、3：不确定**。不用画框、分配 ID 或在大图里寻找对象。图像尚未加载时禁止提交，避免误判上一题。
3. 三种方法若选中同一个候选，只问一次。方法来源在判断前隐藏，减少倾向性。
4. 首选都判否后，程序最多补问三个候选。仍未找到正例就保留为未解决，不强迫做完所有候选；可以从“补充纠错”继续查看。
5. **Z** 或按钮可撤销；刷新、关闭后记录仍在。误判可从样本及候选下拉框选回并修改。
6. “查看本例三方法对比”在该例所有首选都有回答后解锁。统计面板和 `exports` 会随反馈更新。

默认先审核“随机复核”。不必一次做完，先做 10–20 例熟悉操作即可；只做一部分时不能将结果当作全样本结论。

## 本次数据与工作量

- 使用现有去畸变 60 秒、600 帧、2560×1920 视频。
- 检测使用现有 TrackTrack 实验的 **YOLOX tracker_input80 缓存**，不是另跑 YOLO11，也没有改变检测阈值。两帧独立读取，所有三种条件共享相同框及候选。
- 有效总体 5,444 个“上一帧检测框 → 当前帧候选集合”查询；其中 2,110 个存在方法首选分歧。有效姿态限制、投影有效性与排除项见 `dataset.json`。
- 固定随机种子 20260927。从总体均匀、不放回抽取 60 个随机查询，再从未抽中的分歧查询抽取 30 个诊断查询。不是按算法是否成功挑例；同一帧可包含不同来源人物。
- 共 90 个样本、147 个去重后的首选判断，另可能追加纠错。随机集与分歧集分别统计，不能合并为总体准确率。
- 只准备选中样本的 146 张上下文图，约 81 MB，全部位于 E 盘。

## 固定比较协议

三条件：不补偿、原 RGB VideoStab 补偿、Aria 纯旋转补偿。三者都将上一帧框四角投影并取水平外接框，不裁切外接框，避免引入不同的边界处理。没有卡尔曼、外观、历史方向或连续 ID 状态；每例重新从上一帧检测框开始。

主分数：预测框中心到各候选中心的欧氏距离，除以同一个源框对角线。所有候选保留，无 IoU 硬门限；等分时固定按检测缓存索引排序，并记录并列。另记录独立的 IoU 排名，不调权重拼接。

Aria 使用已经验证的 `rectified_v1/relative_rotations.npz` 和去畸变 K；设备—相机外参已经纳入相对旋转。轨迹无效的相邻帧不填假姿态，不使用 RGB 兜底混入 Aria 条件。

RGB 使用之前实际用于 TrackTrack 的原缓存，方向是上一帧到当前帧，首帧为单位变换。原缓存有 **472/600 帧 estimator fallback**，沿用前一次矩阵。逐例展示并导出回退状态。这是对现有实现的对照，不能代表所有 RGB 方法的最佳性能。

## 统计含义

- 首选同人率只使用该首选被人工直接判断的结果。“不确定”和“未判断”不是错误，分别报告。
- 全样本下界 = 已确认首选正确数 / 总样本数；上界 = (总数 − 已确认首选错误数) / 总数。大量未审核时上下界很宽是正常现象。
- 确认至少一个正例后，才可以分析“双方都有检测”的条件子集。`summary.json` 单独报告这个子集的首选同人率。
- 正例排名/中心误差针对**已确认正例**。多个候选可能都框住同一个人，允许多个 yes，不能据此反向推定其他候选都是 no；多正例数量单独报告。
- 匹配余量只对**已经人工否定的候选**计算，命名为 `margin_to_reviewed_negative`。没有穷尽所有候选时，不冒充“所有错误候选中的最近一个”的余量。
- Aria 对另两种方法的“由错变对/由对变错”，只用两种首选都被明确判断的共同样本。按固定 5 秒时间块重采样 1,000 次计算描述性 95% 区间，少于四个已审核块时不出区间。部分审核及诊断集不能支持总体结论。
- 分组输出按相邻旋转量（3.316°/5.323°）、源框对角线（160/400 px）、候选数（5/10）及 RGB 回退状态划分。角度阈值沿用先前无标签背景实验分位数，其余阈值预先固定。
- 只有一段录制；Aria 姿态采用离线插值，不能拿这些结果冒充未来 RGB-only 模型性能或严格在线成绩。

## 文件与安全

正式数据目录：`E:/New_research/outputs/aria_rotation_match_review/v1`。

- `dataset.json`、`manifest.json`：固定查询、三方法分数、抽样协议和输入哈希。
- `frames/`：审核所需图像副本，原视频未改动。
- `review.sqlite3`：本地判断和追加式事件日志，绑定数据集 SHA256，防止加载到另一套样本；不含模型自动伪标签。
- `exports/pair_labels.csv`：明确的人工框对反馈。
- `exports/query_method_results.csv`：逐样本、逐方法的排名与结果。
- `exports/grouped_results.csv`、`summary.json`、`REPORT_ZH.md`：分组、配对和总体进度。

每次确认后先事务保存数据库，再原子更新派生导出。旧判断修改、撤销都保留事件记录。网页仅绑定 `127.0.0.1`，无外部资源与上传接口；写请求带会话令牌并检查来源。多个页面冲突会拒绝过期提交，不默默覆盖。

正式审核库初始化为零判断。浏览器测试在独立 `ui_smoke` 数据库进行，其模拟反馈不属于研究数据。

## 与学习模型的关系

当前是人工在环的模型/规则评估和纠错工具，不是强化学习训练。它提供显式同人/非同人监督，可在后续用于关联模型微调、难例挖掘或偏好学习。没有自动训练、跨帧标签传播或根据审核结果调整本轮评分。

基础模型是否已经具备足够的同人判断能力，需要另设固定模型基线检验，不能把这个假设当成标签质量保证。若后续训练，必须先按时间段/录制隔离训练和测试；本轮已反复审核的难例不能再作为无污染测试集。
